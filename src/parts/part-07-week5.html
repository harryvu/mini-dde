Contracts & waves

DDE's build discipline in one line: build to contracts, never to running code. Events and API contracts carry JSON Schemas inside the graph; producer/consumer choreography is the dependency model; a planner turns that model into parallel build waves; and a context package hands each builder everything it needs in one call. This week you build all four.

  • Concept: the contract IS the specification
  • Build: Event/Contract nodes + validate_schema
  • Build: compute_wave_plan (Kahn's algorithm, cycle-refusal)
  • Build: query_context_package
5.1Events & contracts carry schemasvalidate_schema▶

An Event node is choreography currency: a name like c2c.contract.booked, a JSON Schema stored inline, an example payload. A Contract node covers request/response APIs and data DDL, with a status lifecycle of its own: SPECIFIED → BUILT → VERIFIED — specified at design, built when code exists, verified at integration. The schema travels inside the node, so one query gives a builder the exact shape to code against; a real schema validator makes "conforms to the contract" a machine question.

In the real system

Event at model.go:337-347, Contract at :349-363. query_contract is deliberately thin: try Contract by id, fall back to Event, return the full node — the schema is the payload. validate_schema compiles with santhosh-tekuri/jsonschema/v6 and returns path-addressed errors. Event names follow c2c.{entity}.{past-tense-state} (ADR-event-naming-convention-N0SS).

    package graph

import (
	"context"
	"encoding/json"
	"fmt"
	"strings"

	"github.com/santhosh-tekuri/jsonschema/v6"
)

type SchemaError struct {
	Path    string `json:"path"`
	Message string `json:"message"`
}

// ValidateAgainst compiles a JSON Schema (given as a string) and
// validates a payload, returning per-path errors — real Draft
// validation, not field-name eyeballing.
func ValidateAgainst(schemaJSON string, payload []byte) (bool, []SchemaError, error) {
	var doc any
	if err := json.Unmarshal([]byte(schemaJSON), &doc); err != nil {
		return false, nil, fmt.Errorf("schema_invalid_json: %w", err)
	}
	c := jsonschema.NewCompiler()
	if err := c.AddResource("mem://contract.json", doc); err != nil {
		return false, nil, fmt.Errorf("schema_add: %w", err)
	}
	sch, err := c.Compile("mem://contract.json")
	if err != nil {
		return false, nil, fmt.Errorf("schema_compile: %w", err)
	}
	var inst any
	if err := json.Unmarshal(payload, &inst); err != nil {
		return false, nil, fmt.Errorf("payload_invalid_json: %w", err)
	}
	if err := sch.Validate(inst); err != nil {
		var out []SchemaError
		if ve, ok := err.(*jsonschema.ValidationError); ok {
			for _, cause := range ve.Causes {
				out = append(out, SchemaError{
					Path:    "/" + strings.Join(anyToStrings(cause.InstanceLocation), "/"),
					Message: cause.ErrorKind.LocalizedString(nil),
				})
			}
			if len(out) == 0 {
				out = append(out, SchemaError{Path: "/", Message: ve.Error()})
			}
		} else {
			out = append(out, SchemaError{Path: "/", Message: err.Error()})
		}
		return false, out, nil
	}
	return true, nil, nil
}

func anyToStrings(in []string) []string { return in }

// ValidateEventPayload: resolve the node (Contract first, Event
// fallback — the query_contract order), pick its schema, validate.
func (s *Store) ValidateEventPayload(ctx context.Context, id string, payload []byte) (bool, []SchemaError, error) {
	n, err := s.GetNode(ctx, id)
	if err != nil {
		return false, nil, err
	}
	schemaStr, _ := n.Props["schema"].(string)
	if schemaStr == "" {
		schemaStr, _ = n.Props["request_schema"].(string)
	}
	if schemaStr == "" {
		return false, nil, fmt.Errorf("no_schema: %s carries no schema/request_schema", id)
	}
	return ValidateAgainst(schemaStr, payload)
}

Why it exists

"Not built yet" is never a reason to skip implementation — the contract IS the specification (.claude/rules/bld-contract-compliance.md). That only holds if contracts are precise enough to validate against mechanically. A schema nobody can run is a wish; validate_schema is what makes it law.

5.2Choreography is the dependency modelPRODUCES / CONSUMES▶

Nowhere in DDE does anyone declare "billing depends on booking." Dependency is derived from event choreography: if booking PRODUCES an event that billing CONSUMES, billing depends on booking — full stop. The consequence cuts both ways: model the edges and the planner sees the truth; forget an edge and the dependency does not exist to any downstream machinery.

In the real system

The planner's Cypher reads exactly one pattern: (producer)-[:PRODUCES]->(e:Event)<-[:CONSUMES]-(consumer) (wave.go:167-169). Each pair becomes one WP-level edge: the consumer's first WP depends on the producer's last WP — the coarsest ordering that guarantees the producer is fully built first. Even infrastructure enters the ordering only as CONSUMES edges on capability events (.claude/rules/bld-graph-maintenance.md).

    server/internal/graph/choreography.go
    package graph

import (
	"context"
	"sort"

	"github.com/neo4j/neo4j-go-driver/v5/neo4j"
)

// seqOf normalizes the sequence property: JSON hands you float64,
// Bolt hands you int64 — never assert one blindly.
func seqOf(n Node) int64 {
	switch v := n.Props["sequence"].(type) {
	case int64:
		return v
	case float64:
		return int64(v)
	}
	return 0
}

// wpsOf returns a responsibility's WorkPackages ordered by sequence
// (id tie-break) — determinism matters: identical graphs must yield
// identical plans.
func (s *Store) wpsOf(ctx context.Context, respID string) ([]Node, error) {
	edges, err := s.Neighbors(ctx, respID, "in", EdgeBelongsTo)
	if err != nil {
		return nil, err
	}
	var wps []Node
	for _, e := range edges {
		n, err := s.GetNode(ctx, e.Src)
		if err != nil {
			return nil, err
		}
		wps = append(wps, n)
	}
	sort.Slice(wps, func(i, j int) bool {
		if seqOf(wps[i]) != seqOf(wps[j]) {
			return seqOf(wps[i]) < seqOf(wps[j])
		}
		return wps[i].ID < wps[j].ID
	})
	return wps, nil
}

// ChoreographyDeps derives WP→WP dependencies from PRODUCES/CONSUMES.
// The MATCH below is the real wave planner's pattern VERBATIM
// (builder/server/internal/graph/wave.go:167-169) — one line of
// Cypher expressing "consumer depends on producer through an event".
// For each pair: the consumer's FIRST wp depends on the producer's
// LAST wp.
func (s *Store) ChoreographyDeps(ctx context.Context) (map[string][]string, error) {
	res, err := s.run(ctx, `
		MATCH (producer:Responsibility)-[:PRODUCES]->(e:Event)<-[:CONSUMES]-(consumer:Responsibility)
		WHERE producer.project_id = $pid AND consumer.project_id = $pid
		  AND producer.id <> consumer.id
		RETURN DISTINCT producer.id AS p, consumer.id AS c`, nil)
	if err != nil {
		return nil, err
	}
	deps := map[string][]string{} // wp → the wps it depends on
	for _, rec := range res.Records {
		p, _, _ := neo4j.GetRecordValue[string](rec, "p")
		c, _, _ := neo4j.GetRecordValue[string](rec, "c")
		pWPs, err := s.wpsOf(ctx, p)
		if err != nil {
			return nil, err
		}
		cWPs, err := s.wpsOf(ctx, c)
		if err != nil {
			return nil, err
		}
		if len(pWPs) == 0 || len(cWPs) == 0 {
			continue
		}
		first, last := cWPs[0].ID, pWPs[len(pWPs)-1].ID
		deps[first] = append(deps[first], last)
	}
	return deps, nil
}

5.3The wave plannercompute_wave_plan▶

A wave is a set of work packages whose dependencies are all satisfied by earlier waves — the parallel-execution unit for dispatching builders. The planner merges three dependency sources (explicit DEPENDS_ON edges, derived choreography, implicit within-responsibility sequence), then runs Kahn's algorithm. The design decision worth tattooing somewhere: on a cycle, it persists nothing and fails loudly, naming the members — a silently-persisted cyclic plan yields zero claimable work packages and looks like success.

In the real system

wave.go:32-76: load WPs → adjacency from explicit + choreography + sequential (a sequential edge that would close a cycle is skipped via a reachability check) → Kahn with sorted queues for determinism → wave = max(dep waves) + 1 → cycle members reported, nothing persisted (compute_wave_plan.go:31-39). Persisted derived edges are tagged computed_by = "compute_wave_plan" and excluded from the next run's input — a planner must never eat its own output.

Tasks

  1. Implement the planner:

    server/internal/graph/wave.go
    package graph

import (
	"context"
	"fmt"
	"sort"
)

type Wave struct {
	Number       int      `json:"number"`
	WorkPackages []string `json:"work_packages"`
}

type WavePlan struct {
	Waves          []Wave   `json:"waves"`
	TotalWaves     int      `json:"total_waves"`
	MaxParallelism int      `json:"max_parallelism"`
	Cycles         []string `json:"cycles,omitempty"`
}

func (s *Store) ComputeWavePlan(ctx context.Context) (WavePlan, error) {
	wps, err := s.QueryAll(ctx, "WorkPackage", "")
	if err != nil {
		return WavePlan{}, err
	}
	deps := map[string]map[string]bool{} // wp → set of wps it depends on
	add := func(wp, dep string) {
		if deps[wp] == nil {
			deps[wp] = map[string]bool{}
		}
		deps[wp][dep] = true
	}
	for _, wp := range wps {
		deps[wp.ID] = deps[wp.ID] // ensure key exists
	}

	// Source 1: explicit DEPENDS_ON edges.
	for _, wp := range wps {
		out, err := s.Neighbors(ctx, wp.ID, "out", EdgeDependsOn)
		if err != nil {
			return WavePlan{}, err
		}
		for _, e := range out {
			add(wp.ID, e.Dst)
		}
	}
	// Source 2: choreography (lesson 5.2).
	choreo, err := s.ChoreographyDeps(ctx)
	if err != nil {
		return WavePlan{}, err
	}
	for wp, ds := range choreo {
		for _, d := range ds {
			add(wp, d)
		}
	}
	// Source 3: implicit sequence within each Responsibility.
	resps, err := s.QueryAll(ctx, "Responsibility", "")
	if err != nil {
		return WavePlan{}, err
	}
	for _, r := range resps {
		seq, err := s.wpsOf(ctx, r.ID)
		if err != nil {
			return WavePlan{}, err
		}
		for i := 1; i < len(seq); i++ {
			add(seq[i].ID, seq[i-1].ID)
		}
	}

	// Kahn's algorithm with sorted queues for determinism.
	wave := map[string]int{}
	remaining := map[string]map[string]bool{}
	for wp, ds := range deps {
		remaining[wp] = map[string]bool{}
		for d := range ds {
			remaining[wp][d] = true
		}
	}
	for {
		var ready []string
		for wp, ds := range remaining {
			if len(ds) == 0 {
				ready = append(ready, wp)
			}
		}
		if len(ready) == 0 {
			break
		}
		sort.Strings(ready)
		for _, wp := range ready {
			w := 1
			for d := range deps[wp] {
				if dw, ok := wave[d]; ok && dw >= w {
					w = dw + 1
				}
			}
			wave[wp] = w
			delete(remaining, wp)
			for _, ds := range remaining {
				delete(ds, wp)
			}
		}
	}

	// Anything left is a cycle member: REFUSE, persist nothing.
	if len(remaining) > 0 {
		var members []string
		for wp := range remaining {
			members = append(members, wp)
		}
		sort.Strings(members)
		return WavePlan{Cycles: members},
			fmt.Errorf("dependency_cycle: %v — fix the graph; an unaddressed "+
				"cycle leaves zero claimable work packages", members)
	}

	// Persist wave numbers; assemble the plan.
	byWave := map[int][]string{}
	maxW, maxPar := 0, 0
	for wp, w := range wave {
		byWave[w] = append(byWave[w], wp)
		if w > maxW {
			maxW = w
		}
	}
	var plan WavePlan
	for w := 1; w <= maxW; w++ {
		sort.Strings(byWave[w])
		if len(byWave[w]) > maxPar {
			maxPar = len(byWave[w])
		}
		plan.Waves = append(plan.Waves, Wave{Number: w, WorkPackages: byWave[w]})
		for _, wp := range byWave[w] {
			s.UpdateNode(ctx, wp, map[string]any{"wave": w})
		}
	}
	plan.TotalWaves, plan.MaxParallelism = maxW, maxPar
	return plan, nil
}

5.4Context packagesquery_context_package▶

Before a builder agent writes a line of code, it makes one call: query_context_package(responsibility) — and receives the responsibility, the full specification text, every consumed and produced event with schemas, governing decisions, applicable patterns, open findings, and its work packages. Self-contained context is what makes autonomous build possible: no grepping, no guessing, no "I'll just look at the sibling service."

In the real system

AssembleContext (internal/context/assembler.go:105-131): Responsibility + SDD body read from disk via the DOCUMENTED_BY Document's path + events on CONSUMES/PRODUCES + GOVERNED_BY decisions + patterns (universal or domain-matched) + findings bucketed by status + WPs + the variant's DoD checklist. Default is a lean projection (inline bodies stripped, recoverable by path) — payload size is a first-class design concern when your consumer is a context window.

Tasks

  1. Define the package and assemble it:

    server/internal/graph/context.go
    package graph

import (
	"context"
	"os"
)

type ContextPackage struct {
	Responsibility Node   `json:"responsibility"`
	Specification  string `json:"specification"`
	EventsConsumed []Node `json:"events_consumed"`
	EventsProduced []Node `json:"events_produced"`
	Decisions      []Node `json:"decisions"`
	OpenFindings   []Node `json:"open_findings"`
	WorkPackages   []Node `json:"work_packages"`
}

func (s *Store) AssembleContext(ctx context.Context, respID string) (ContextPackage, error) {
	var pkg ContextPackage
	resp, err := s.GetNode(ctx, respID)
	if err != nil {
		return pkg, err
	}
	pkg.Responsibility = resp

	// Specification: follow DOCUMENTED_BY to a Document, read its
	// path from disk — the one intentional full-text copy.
	docs, _ := s.Neighbors(ctx, respID, "out", EdgeDocumentedBy)
	for _, e := range docs {
		d, err := s.GetNode(ctx, e.Dst)
		if err != nil {
			continue
		}
		if path, ok := d.Props["path"].(string); ok {
			if body, err := os.ReadFile(path); err == nil {
				pkg.Specification = string(body)
				break
			}
		}
	}

	collect := func(dir, edgeType string) []Node {
		var out []Node
		edges, _ := s.Neighbors(ctx, respID, dir, edgeType)
		for _, e := range edges {
			other := e.Dst
			if dir == "in" {
				other = e.Src
			}
			if n, err := s.GetNode(ctx, other); err == nil {
				out = append(out, n)
			}
		}
		return out
	}
	pkg.EventsConsumed = collect("out", EdgeConsumes)
	pkg.EventsProduced = collect("out", EdgeProduces)
	pkg.Decisions = collect("out", EdgeGovernedBy)
	pkg.WorkPackages = collect("in", EdgeBelongsTo)
	for _, f := range collect("in", EdgeAffects) {
		if f.Status == "OPEN" {
			pkg.OpenFindings = append(pkg.OpenFindings, f)
		}
	}
	return pkg, nil
}

Why it exists

The real assembler strips inline bodies by default (ADR-lean-default-projection-P6EA) and has a budget mode with per-phase BFS depths and a 500-node cap. Why? Because the consumer is a context window: an over-eager context package can crowd out the model's working room as surely as a thin one starves it. Payload discipline is agent ergonomics.
