Week 2 · Part I — the graph kernel

Governed mutation

A graph anyone can write anything to is a wiki with extra steps. DDE's real power is that every mutation passes a rule at the write boundary: statuses move only along a state machine, IDs are minted by the server, required edges are created inside the write, and validators run in named chains. This week your store stops being a bag of rows and starts being governed.

  • Concept: transition maps + the one legitimate status writer
  • Build: update_status with changelog; content-addressed ID allocator
  • Build: required-edge contracts; validator chains
  • Habit: structured errors — code: human message
2.1Status is a state machineupdate_status▶

Every tracked node type carries a transition map — the complete list of legal from→to moves. There is exactly one legitimate status writer, update_status, which validates the transition, demands a reason, records a changelog entry, and rejects same-status writes. Setting status through a generic property update is forbidden — that's the difference between a lifecycle and a text field.

In the real system

Maps live in model.go (Responsibility at :1709-1734, WorkPackage :1737-1779, Finding :1789-1798); the generic checker is ValidateTransition (:1946-1957). update_status.go picks the map, requires reason, writes atomically, records a ChangelogEntry, and emits a status_changed event. update_node rejects any status key on a mapped type with "use update_status instead" — the rule .claude/rules/bld-status-transitions.md, mechanically enforced.

		// CONFIRMED, REJECTED, DEFERRED: terminal — no exits.
	},
	"Escalation": {
		"":        {"pending"},
		"pending": {"resolved", "expired"},
	},

func ValidateTransition(nodeType, from, to string) error {
	m, tracked := Transitions[nodeType]
	if !tracked {
		return nil // untracked types have free-form status
	}
	if from == to {
		return fmt.Errorf("same_status: %s is already %q", nodeType, from)
	}
	for _, legal := range m[from] {
		if legal == to {
			return nil
		}
	}
	return fmt.Errorf("invalid_transition: %s %q → %q is not in the map", nodeType, from, to)
}

  2. Write the one status writer — with a mandatory reason and a changelog:

    server/internal/graph/status.go
    package graph

import (
	"fmt"
	"time"
)

const changelogSchema = `
CREATE TABLE IF NOT EXISTS changelog (
  project_id TEXT NOT NULL, node_id TEXT NOT NULL,
  from_status TEXT, to_status TEXT, reason TEXT NOT NULL,
  at TEXT NOT NULL
);`

// UpdateStatus is the ONLY path that may change a node's status.
func (s *Store) UpdateStatus(id, to, reason string) error {
	if reason == "" {
		return fmt.Errorf("reason_required: every transition records why")
	}
	n, err := s.GetNode(id)
	if err != nil {
		return err
	}
	if err := ValidateTransition(n.Type, n.Status, to); err != nil {
		return err
	}
	tx, err := s.db.Begin()
	if err != nil {
		return fmt.Errorf("begin tx: %w", err)
	}
	defer tx.Rollback()
	now := time.Now().UTC().Format(time.RFC3339)
	if _, err := tx.Exec(
		`UPDATE nodes SET status = ?, updated_at = ? WHERE id = ? AND project_id = ?`,
		to, now, id, s.projectID); err != nil {
		return fmt.Errorf("update status: %w", err)
	}
	if _, err := tx.Exec(
		`INSERT INTO changelog (project_id, node_id, from_status, to_status, reason, at)
		 VALUES (?, ?, ?, ?, ?, ?)`,
		s.projectID, id, n.Status, to, reason, now); err != nil {
		return fmt.Errorf("changelog: %w", err)
	}
	return tx.Commit()
}

    Add changelogSchema to the schema constant in store.go (or exec it in Open). Status + changelog commit in one transaction — a transition without its audit row never exists.

Why it exists

The real system pairs this with a structural twist worth knowing now: an Outcome's status is derived from its members and update_status rejects it outright with the structured error outcome_status_is_derived — you move an Outcome by moving its members. Derived state gets a sole server-side writer; direct writes get a named refusal. You'll build a tiny version of that rollup in week 7.

2.2Content-addressed IDsallocator▶

Decision records get IDs like ADR-outcome-graph-primitive-MHMV: a type, a slug derived from the title, and a random 4-char suffix. Never sequential. Sequential numbering needs a central counter, and the moment two agent sessions author records in parallel branches, counters collide. Content-addressed IDs are allocated server-side, atomically, and a record's identity never depends on authoring order.

In the real system

DeriveSlug lives in builder/server/internal/graph/decision_id.go: lowercase, stop-words removed, max 3 meaningful words, max 32 chars. Suffixes are crypto/rand Crockford base32 — alphabet 0123456789ABCDEFGHJKMNPQRSTVWXYZ, no I/L/O/U, for speakability. Allocate (allocator.go:86-110) retries 8 candidates at width 4, widening to 5 then 6, each attempt one atomic statement. Governance is Builder ADR-atomic-id-allocator-H37G; the caller-supplied-ID ban is ADR-id-canonicalization-server-ZRZ5 — "server allocates, disk follows".

Tasks

  1. Implement slug derivation + suffix generation:

    server/internal/graph/allocator.go
    package graph

import (
	"crypto/rand"
	"fmt"
	"regexp"
	"strings"
)

// Crockford base32 minus the confusable letters I, L, O, U.
const suffixAlphabet = "0123456789ABCDEFGHJKMNPQRSTVWXYZ"

var stopWords = map[string]bool{
	"a": true, "the": true, "for": true, "of": true, "in": true,
	"to": true, "and": true, "with": true, "on": true, "at": true,
}
var nonAlnum = regexp.MustCompile(`[^a-z0-9]+`)

// DeriveSlug: lowercase, drop stop-words, keep at most 3 meaningful
// words, cap at 32 chars on a word boundary, kebab-case.
func DeriveSlug(title string) string {
	words := nonAlnum.Split(strings.ToLower(title), -1)
	var kept []string
	for _, w := range words {
		if w == "" || stopWords[w] {
			continue
		}
		kept = append(kept, w)
		if len(kept) == 3 {
			break
		}
	}
	slug := strings.Join(kept, "-")
	for len(slug) > 32 {
		if i := strings.LastIndex(slug, "-"); i > 0 {
			slug = slug[:i]
		} else {
			slug = slug[:32]
		}
	}
	if slug == "" {
		slug = "record"
	}
	return slug
}

func GenerateSuffix(width int) (string, error) {
	b := make([]byte, width)
	if _, err := rand.Read(b); err != nil {
		return "", fmt.Errorf("entropy: %w", err)
	}
	out := make([]byte, width)
	for i, v := range b {
		out[i] = suffixAlphabet[int(v)%len(suffixAlphabet)]
	}
	return string(out), nil
}

  2. Allocate atomically with bounded retry. The candidate is TYPE-slug-SUFFIX; a collision re-rolls; suffix width widens 4→5→6 before giving up:

    server/internal/graph/allocator.go (append)
    // AllocateDecisionID mints a canonical id: TYPE-slug-XXXX. Uniqueness
// rides the (id, project_id) primary key — INSERT wins or collides,
// there is no read-then-write race.
func (s *Store) AllocateDecisionID(docType, title string) (string, error) {
	dt := strings.ToUpper(docType) // ADR | PDR | DDR | WOW | CIR
	slug := DeriveSlug(title)
	for width := 4; width <= 6; width++ {
		for attempt := 0; attempt < 8; attempt++ {
			sfx, err := GenerateSuffix(width)
			if err != nil {
				return "", err
			}
			id := fmt.Sprintf("%s-%s-%s", dt, slug, sfx)
			res, err := s.db.Exec(`
				INSERT INTO nodes (id, project_id, type, status, props, created_at, updated_at)
				VALUES (?, ?, 'Decision', 'Proposed', '{}',
				        strftime('%Y-%m-%dT%H:%M:%SZ','now'),
				        strftime('%Y-%m-%dT%H:%M:%SZ','now'))
				ON CONFLICT DO NOTHING`, id, s.projectID)
			if err != nil {
				return "", fmt.Errorf("allocate: %w", err)
			}
			if n, _ := res.RowsAffected(); n == 1 {
				return id, nil // we created it — the id is ours
			}
			// collision: re-roll
		}
	}
	return "", fmt.Errorf("retry_exhausted: could not allocate id for %q", title)
}

    Note what makes it atomic: the INSERT … ON CONFLICT DO NOTHING + RowsAffected check is one statement — the same trick the real server plays with a single Cypher MERGE carrying an ON-CREATE marker.

The slug is derived once at allocation and never recomputed. Also assert: suffixes never contain I, L, O, or U; two allocations with the same title yield different IDs.

2.3Edge contracts & server-minted edgesrequired edges▶

Some edges aren't optional decoration — they're part of what makes a node valid. In the real system a new Responsibility must carry at least one lineage edge (where did this work come from — a CIR? a Decision? a Finding?) in the same create call, and each lineage target must already exist. The deeper principle: required edges are created inside the write, never left to a second client call that might never come.

In the real system

ValidLineageEdges = {ORIGINATED_FROM, GOVERNED_BY, SPAWNED_FROM, DERIVED_FROM} (model.go:1162-1167); ≥1 required per new Responsibility, targets existence-checked before persist (create_node.go:415-440). register_finding goes further: it writes the Finding, mints AFFECTS/FOUND_IN, then re-reads the edges and rolls the whole Finding back if they failed to land — a rolled-back finding is never embedded, changelogged, or notified.

Tasks

  1. Add bundled-edge creation. Extend the store with a create-with-edges API and a lineage contract:

    server/internal/graph/contracts.go
    package graph

import "fmt"

var lineageEdges = map[string]bool{
	"ORIGINATED_FROM": true, "GOVERNED_BY": true,
	"SPAWNED_FROM": true, "DERIVED_FROM": true,
}

// BundledEdge is an edge requested as part of a create_node call.
// Src "" means "the node being created".
type BundledEdge struct {
	Src, Dst, Type string
}

// CreateNodeWithEdges enforces per-type edge contracts, then writes
// node + edges together. Responsibility: ≥1 lineage edge whose target
// already exists.
func (s *Store) CreateNodeWithEdges(n Node, edges []BundledEdge) error {
	if n.Type == "Responsibility" {
		hasLineage := false
		for _, e := range edges {
			if lineageEdges[e.Type] {
				if _, err := s.GetNode(e.Dst); err != nil {
					return fmt.Errorf("lineage_target_missing: %s: %w", e.Dst, err)
				}
				hasLineage = true
			}
		}
		if !hasLineage {
			return fmt.Errorf("lineage_required: a Responsibility must declare " +
				"where it came from (ORIGINATED_FROM | GOVERNED_BY | SPAWNED_FROM | DERIVED_FROM)")
		}
	}
	if err := s.CreateNode(n); err != nil {
		return err
	}
	for _, e := range edges {
		src := e.Src
		if src == "" {
			src = n.ID
		}
		if err := s.CreateEdge(src, e.Dst, e.Type); err != nil {
			// verify-and-rollback: a node without its contract edges
			// must not survive.
			s.db.Exec(`DELETE FROM nodes WHERE id = ? AND project_id = ?`,
				n.ID, s.projectID)
			return fmt.Errorf("bundled_edge_failed (node rolled back): %w", err)
		}
	}
	return nil
}

    Add the four lineage edge types to ValidEdgeTypes. (Real nuance you're mirroring: some bundled edges are inbound-only and direction-checked; keep that in mind rather than in code for now.)

  3. Test both failure modes: a Responsibility with no lineage edge → lineage_required; with a lineage edge to a ghost id → lineage_target_missing and (assert!) the node does not exist afterwards.

Why it exists

Lineage answers the question every future maintainer asks: why does this work exist? In the real graph, ADR-053 made the quartet mandatory after unlabeled Responsibilities piled up with no traceable origin — the graph equivalent of code with no commit history.

2.4Validators at the boundaryvalidator chains▶

Validation in DDE is not scattered if statements — it's ordered chains of named validators run at the write boundary, each returning either a structured rejection or nil. Two conventions make the pattern scale: errors lead with a machine-parseable code (lineage_required: … — you've been doing this since 2.1 without noticing), and every covered node type gets a plain-English eli10 summary so the graph stays legible to humans.

In the real system

update_node.go:188-220 runs a 14-validator chain — the load-bearing one rejects any status key with "use update_status instead". validate_eli10.go checks: 80–350 bytes, single paragraph, no code fences, ≤2 inline-code spans, unexpanded acronyms only from a 23-entry allowlist. Presence is enforced when ELI10_ENFORCE=1; malformed values are always rejected. Errors follow the three-tier contract: ToolError with a leading code, sentinel errors, pinned JSON-RPC codes.

Tasks

  1. Define the chain type and refit CreateNodeWithEdges:

    server/internal/graph/validators.go
    package graph

import (
	"fmt"
	"strings"
)

// A Validator inspects a node about to be written and returns a
// structured error ("code: message") or nil. Chains run in order;
// first rejection wins.
type Validator func(n Node) error

var CreateValidators = []Validator{
	validateKnownType,
	validateEli10,
	validateNoCallerStatus,
}

func validateKnownType(n Node) error {
	if !ValidNodeTypes[n.Type] {
		return fmt.Errorf("unknown_type: %q", n.Type)
	}
	return nil
}

// eli10 required on the PCC-surfaced types; always shape-checked.
var eli10Types = map[string]bool{
	"Responsibility": true, "Decision": true, "Finding": true,
	"WorkPackage": true, "Pattern": true, "Verdict": true,
}

func validateEli10(n Node) error {
	raw, ok := n.Props["eli10"].(string)
	if !ok || raw == "" {
		if eli10Types[n.Type] {
			return fmt.Errorf("eli10_required: %s nodes carry a plain-English "+
				"summary (80-350 chars) so operators can read the graph", n.Type)
		}
		return nil
	}
	if len(raw) < 80 || len(raw) > 350 {
		return fmt.Errorf("eli10_length: got %d chars, want 80-350", len(raw))
	}
	if strings.Contains(raw, "\n\n") || strings.Contains(raw, "```") {
		return fmt.Errorf("eli10_shape: single paragraph, no code fences")
	}
	return nil
}

// Terminal-ish statuses may not be set at create time; nodes are born
// at the map's initial status and move via UpdateStatus.
func validateNoCallerStatus(n Node) error {
	if _, tracked := Transitions[n.Type]; tracked && n.Status != "" {
		if err := ValidateTransition(n.Type, "", n.Status); err != nil {
			return fmt.Errorf("caller_supplied_status: %w", err)
		}
	}
	return nil
}

    Call the chain at the top of CreateNodeWithEdges (and CreateNode): for _, v := range CreateValidators { if err := v(n); err != nil { return err } }.

Why it exists

The eli10 layer sounds cosmetic until you watch an operator triage a graph of 400 nodes at 11pm. The PCC renders the eli10 as the leading line of every card — and renders a visible "no plain-English summary yet" badge when it's missing. Absence is surfaced, never hidden; that badge is the entire backfill-pressure mechanism. Governance: ADR-eli10-pcc-nodes-ASXB.
