Week 3 · Part II — governance & agents

Decisions & findings

Now the graph learns to carry authority. Decisions live twice — a markdown record on disk (canonical content) and a Decision node in the graph (queryable edges) — and once Accepted they are immutable: change means supersession, atomically and symmetrically. Findings and escalations are the graph's memory of open questions, with a lifecycle, required edges, and an audit trail that survives everyone's context window.

  • Concept: the artefact taxonomy — ADR / PDR / DDR / WoW / CIR
  • Build: disk templates + graph mirror + supersession
  • Build: a governance lint; register_finding / escalations
  • Doctrine: zero internal deferrals
3.1Decision records on disk (xDRs)taxonomy▶

Five record types split the space of "things we decided," and the split is the point — an author who knows which record to write has already understood the decision. ADR: how the system is built (technology, pattern, layer). PDR: what the product does and why. DDR: how data flows (schema, ownership, keys, state machines). WoW: how the team operates (process, gates, authority). CIR: a pre-decision idea record that feeds the promote flow. Rule of thumb from the framework: a rule without a record is a smell.

In the real system

The authoring decision tree: docs/governance-framework.md:60-114. Template: docs/adr/000-template.md. Filenames are lowercase <type>-<slug>-<XXXX>.md; prose citation uses uppercase (ADR-spanner-graph-neo4j-7K9P) — same record, two spellings. Domain-scoped records live at domains/<domain>/docs/{adr,pdr,ddr,cir,wow}/; the corpus manifest scripts/xdr_corpus.py knows every tier.

3.2The graph mirror: register, govern, supersedeGOVERNED_BY▶

The markdown file is canonical content; the graph node is canonical connectivity. Mirroring a record into the graph gives you GOVERNED_BY edges — so a builder can ask "what governs this responsibility?" and get five records instead of grepping all eighty-six. Once Accepted, records are content-immutable: changing one means authoring a new record that supersedes it, updating both files (and both nodes) in the same commit — supersession is atomic and symmetric.

In the real system

Dual-homing per WOW-decision-record-taxonomy-1BNV; a CIR is a Decision node with doc_type="cir", dual-labeled Decision:Document. The status write is mirrored to the paired twin atomically (UpdateMultiLabelInTx). Supersession discipline: the new record's <supersedes> names the old; the old's <superseded-by> names the new; one PR, both files (decision-records.md rules 5–6). A Stop hook even blocks ending a session with an Accepted record left untracked in git.

Tasks

  1. Write RegisterDecision: given a doc type, an allocated id, a disk path, and a title, create/patch the Decision node with doc_type, path, title, and the file's content (cap it — the real server caps disk auto-fill at 256KB):

    server/internal/graph/decisions.go
    package graph

import (
	"fmt"
	"os"
)

func (s *Store) RegisterDecision(id, docType, path, title, eli10 string) error {
	body, err := os.ReadFile(path)
	if err != nil {
		return fmt.Errorf("decision_file_missing: %s: %w", path, err)
	}
	if len(body) > 256<<10 {
		body = body[:256<<10]
	}
	return s.CreateNode(Node{
		ID: id, Type: "Decision", Status: "Proposed",
		Props: map[string]any{
			"doc_type": docType, "path": path, "title": title,
			"content": string(body), "eli10": eli10,
		},
	})
}

// SupersedeDecision retires old in favor of new: both nodes updated,
// SUPERSEDES edge minted, one transaction of intent.
func (s *Store) SupersedeDecision(oldID, newID string) error {
	if _, err := s.GetNode(newID); err != nil {
		return fmt.Errorf("superseding_record_missing: %w", err)
	}
	if err := s.CreateEdge(newID, oldID, EdgeSupersedes); err != nil {
		return err
	}
	if err := s.UpdateStatus(oldID, "Superseded",
		"superseded by "+newID); err != nil {
		return err
	}
	return nil
}

    Add a Decision transition map to Transitions: "" → Proposed; Proposed → {Accepted, Deprecated}; Accepted → {Superseded, Deprecated}. Note what that map forbids: editing an Accepted record back to Proposed, and superseding something that was never accepted (a never-accepted record is Deprecated instead).

3.3Lint the law: mini governance lintlint-decisions▶

Governance that isn't linted rots. The real repo runs a battery of deterministic checks over the record corpus: filename shape, required sections, meta-block integrity, citation symmetry, and a heuristic over the Compliance section that flags "manual review only" as a candidate for stronger enforcement. You'll build the core of that as one bash script — your first piece of the mechanism plane.

In the real system

scripts/lint-decisions.sh (Format A validation + slug-shape caps), scripts/lint-citation-symmetry.py (dangling / unreciprocated supersession pointers), scripts/lint-compliance-claims.py (every "Automated" claim must name its artifact — "a test verifies this" fails). All run from .githooks/pre-commit. The tier doctrine (WOW-lint-guard-rollout-TMNJ): a diff-scoped deterministic check may ship blocking immediately; a full-scan check ships blocking only with a proven-empty baseline; advisory is a state with an owner and an exit criterion, never a resting place.

Tasks

  1. Write the lint:

    scripts/lint-decisions.sh
    #!/usr/bin/env bash
# Mini governance lint: filename shape, meta block, required sections,
# supersession symmetry. Exit 1 on any FAIL.
set -uo pipefail
fails=0
fail() { echo "FAIL  $1: $2"; fails=$((fails+1)); }
pass() { echo "PASS  $1"; }

shopt -s nullglob
for f in docs/{adr,pdr,ddr,wow,cir}/*.md; do
  base=$(basename "$f")
  [[ "$base" == 000-template.md ]] && continue

  # 1. filename: <type>-<slug>-<XXXX>.md, suffix Crockford (no i,l,o,u)
  if [[ ! "$base" =~ ^(adr|pdr|ddr|wow|cir)-[a-z0-9-]+-[0-9A-HJKMNP-TV-Z]{4}\.md$ ]]; then
    fail "$base" "filename must be <type>-<slug>-<XXXX>.md"
    continue
  fi

  # 2. meta block: id matches filename, status is a legal value
  id_in_file=$(grep -o '<id>[^<]*</id>' "$f" | sed 's/<[^>]*>//g')
  want_id=$(echo "${base%.md}" | awk -F- '{printf toupper($1); for(i=2;i<=NF;i++) printf "-"$i}')
  [[ "$id_in_file" == "$want_id" ]] || fail "$base" "meta id '$id_in_file' != filename id '$want_id'"
  status=$(grep -o '<status>[^<]*</status>' "$f" | sed 's/<[^>]*>//g')
  case "$status" in Proposed|Accepted|Superseded|Deprecated) ;; *)
    fail "$base" "illegal status '$status'";; esac

  # 3. required sections
  for sec in "## Context" "## Decision" "## Consequences" "## Compliance"; do
    grep -q "^$sec" "$f" || fail "$base" "missing section '$sec'"
  done

  # 4. compliance heuristic: >=30 chars of substance
  comp=$(awk '/^## Compliance/{flag=1;next}/^## /{flag=0}flag' "$f" | tr -d ' \n')
  [[ ${#comp} -ge 30 ]] || fail "$base" "Compliance section too thin (<30 chars)"

  # 5. supersession symmetry: if I supersede X, X must name me back
  sup=$(grep -o '<supersedes>[^<]*</supersedes>' "$f" | sed 's/<[^>]*>//g')
  if [[ -n "$sup" ]]; then
    lower=$(echo "$sup" | tr 'A-Z' 'a-z')
    old="docs/${lower%%-*}/${lower}.md"
    if [[ ! -f "$old" ]]; then fail "$base" "supersedes '$sup' but $old not found"
    elif ! grep -q "<superseded-by>$want_id</superseded-by>" "$old"; then
      fail "$base" "$old does not point back via <superseded-by>"
    fi
  fi
  pass "$base"
done
echo; echo "$fails failure(s)"
exit $((fails > 0))

  2. Run it, then break it on purpose. Rename a record to a sequential id (adr-001.md), delete a Compliance section, break the supersession backlink — watch each specific FAIL message. A lint you've never seen fail is a lint you can't trust; the real repo takes this further with positive controls: patterns that must match themselves, proving the gate can fire.

  3. Commit the lint and record the decision. Author a tiny WoW: "Decision records are linted; lint failures block commits (wired in week 6)." Governance about governance — status Accepted, registered in the graph, naturally.

Checkpoint

All records PASS; each deliberate breakage produces the right FAIL; exit code is 1 when anything fails (test with echo $?).

3.4Findings & escalationsregister_finding▶

A Finding is the graph's unit of "something is wrong or unknown": a defect, a gap, an ambiguity, discovered mid-work. It has a hard field contract (thin findings are noise), required edges to what it affects, and a lifecycle that ends only in CONFIRMED, REJECTED, or DEFERRED. An Escalation is a question for the decision authority with explicit options. Together they implement the agent doctrine: confusion that is not surfaced becomes fabrication.

In the real system

register_finding enforces: title ≥10, description ≥50, evidence ≥30, recommendation ≥30 chars, severity enum, required classification (19-value taxonomy), server-allocated id, AFFECTS/FOUND_IN edges with a verify-and-rollback gate. resolve_finding: OPEN→RESOLVED only, resolution ≥50 chars, verification_note ≥30. reject_finding: DA only. Escalations: register_escalation with options; resolve_escalation refuses unless status is exactly pending — the lifecycle is tool-owned, no transition map to game.

Tasks

  1. Implement RegisterFinding with the field contract and bundled edges:

    server/internal/graph/findings.go
    package graph

import "fmt"

var severities = map[string]bool{
	"critical": true, "high": true, "medium": true, "low": true,
}

type FindingInput struct {
	Title, Description, Evidence, Recommendation string
	Severity, Classification, ResponsibilityID   string
	Eli10                                        string
}

func (s *Store) RegisterFinding(in FindingInput) (string, error) {
	switch {
	case len(in.Title) < 10:
		return "", fmt.Errorf("finding_title_thin: >=10 chars — name the problem")
	case len(in.Description) < 50:
		return "", fmt.Errorf("finding_description_thin: >=50 chars — a future reader starts from zero")
	case len(in.Evidence) < 30:
		return "", fmt.Errorf("finding_evidence_thin: >=30 chars — what did you SEE?")
	case len(in.Recommendation) < 30:
		return "", fmt.Errorf("finding_recommendation_thin: >=30 chars — what should happen next?")
	case !severities[in.Severity]:
		return "", fmt.Errorf("finding_severity: want critical|high|medium|low")
	case in.Classification == "":
		return "", fmt.Errorf("finding_classification_required: e.g. ambiguous_spec, defect, missing_contract, pattern_violation")
	}
	id, err := s.AllocateID("Finding", "Finding", in.Title, "OPEN")
	if err != nil {
		return "", err
	}
	err = s.patchAndLink(id, map[string]any{
		"title": in.Title, "description": in.Description,
		"evidence": in.Evidence, "recommendation": in.Recommendation,
		"severity": in.Severity, "classification": in.Classification,
		"eli10": in.Eli10,
	}, []BundledEdge{
		{Src: id, Dst: in.ResponsibilityID, Type: EdgeAffects},
		{Src: id, Dst: in.ResponsibilityID, Type: EdgeFoundIn},
	})
	if err != nil {
		// verify-and-rollback: a finding without its edges must not exist.
		s.db.Exec(`DELETE FROM nodes WHERE id=? AND project_id=?`, id, s.projectID)
		return "", fmt.Errorf("finding_edges_failed (rolled back): %w", err)
	}
	return id, nil
}

    Refactor small helpers as needed: generalize lesson 2.2's allocator into AllocateID(nodeType, prefix, title, initialStatus) so Findings mint Finding-<slug>-<XXXX>, and add patchAndLink(id, props, edges) (UpdateNode + CreateEdge loop). Callers never supply finding IDs — server allocates, always.

  2. Implement the lifecycle verbs. ResolveFinding(id, resolution, resolvedBy, verificationNote): reject unless current status is OPEN, resolution ≥50 chars, note ≥30 chars, then UpdateStatus(id, "RESOLVED", …) and patch the resolution fields. ConfirmFinding(id, confirmedBy): RESOLVED→CONFIRMED. RejectFinding(id, rejectedBy, reason): only from OPEN and only when rejectedBy == "decision-authority" — agents never silently kill findings.

  3. Implement escalations as tool-owned lifecycle:

    server/internal/graph/escalations.go
    package graph

import "fmt"

func (s *Store) RegisterEscalation(question string, options []string, eli10 string) (string, error) {
	if question == "" || len(options) < 2 {
		return "", fmt.Errorf("escalation_needs_options: a DA question " +
			"carries >=2 explicit options — never an open 'what should I do?'")
	}
	id, err := s.AllocateID("Escalation", "Escalation", question, "pending")
	if err != nil {
		return "", err
	}
	return id, s.UpdateNode(id, map[string]any{
		"question": question, "options": options, "eli10": eli10,
	})
}

// ResolveEscalation refuses unless status is exactly "pending" —
// the lifecycle is owned by this function, not a transition map.
func (s *Store) ResolveEscalation(id, chosen, resolvedBy string) error {
	n, err := s.GetNode(id)
	if err != nil {
		return err
	}
	if n.Status != "pending" {
		return fmt.Errorf("escalation_not_pending: %s is %q", id, n.Status)
	}
	if err := s.UpdateNode(id, map[string]any{
		"resolution": chosen, "resolved_by": resolvedBy,
	}); err != nil {
		return err
	}
	return s.UpdateStatus(id, "resolved", "DA chose: "+chosen)
}

Resolve it with a real fix and a verification note that names how you verified. Then register an escalation with two options for a real open question (e.g. "should the capstone use one DB or three?"), and resolve it as the DA.

  5. Read the deferral doctrine (below) and add the one mechanical piece: a CheckDeferral(findingID) that returns true only if an ExternalDependency node exists with a BLOCKS edge to the finding — the precondition for the DEFERRED status ever being legal.

Doctrine: zero internal deferrals

Nothing internal to the project is deferrable — not complexity, not effort, not "the sibling isn't built yet" (build against the contract). A deferral is valid only when the dependency is genuinely external and DA authorization is captured: either an ExternalDependency node with a BLOCKS edge (Pattern A, machine-queryable), or a DA-resolved Escalation whose id is quoted verbatim in the finding's verification note (Pattern B, audit-greppable). Your CheckDeferral is Pattern A's validator in miniature.

Checkpoint — end of week 3

A thin finding (49-char description) is rejected with the exact code; a registered finding carries both edges (prove via neighbors); resolve→confirm walks the map; reject requires the DA; CheckDeferral returns false until you create the ExternalDependency + BLOCKS edge, then true.

Why it exists

The field minimums look bureaucratic until you inherit a graph of findings that read "fix later". The real taxonomy went further after measurement: a locally-narrowed reviewer enum misattributed ~42% of finding closures before the canonical enum was enforced at the tool boundary. Contracts on metadata are what keep institutional memory usable.
