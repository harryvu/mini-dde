Tasks

  1. Create the module and the envelope: mkdir -p capstone/pkg && cd capstone/pkg && go mod init minic2c/pkg, add it to go.work.

    capstone/pkg/events/events.go
    package events

import (
	"crypto/sha256"
	"encoding/hex"
	"encoding/json"
	"time"
)

// Event is the shared envelope. Payload stays raw until the concrete
// contract pins the shape — the envelope is transport, not schema.
type Event struct {
	ID            string          `json:"event_id"`       // idempotency key
	Type          string          `json:"event_type"`     // c2c.{entity}.{past-tense-state}
	SchemaVersion string          `json:"schema_version"` // "1.0" default
	OrderingKey   string          `json:"ordering_key"`
	OccurredAt    time.Time       `json:"occurred_at"`
	Payload       json.RawMessage `json:"payload"`
}

// SpineOrderingKey hashes the SAP Contract Number for use as the
// per-contract ordering key. The RAW number never rides transport
// metadata — metadata escapes payload access control (push bodies,
// exports, logs), so the key is an anti-exposure control.
func SpineOrderingKey(sapContractNumber string) string {
	sum := sha256.Sum256([]byte(sapContractNumber))
	return hex.EncodeToString(sum[:])[:16]
}

// Publisher is consumer-defined small: services depend on this, and
// tests inject a RecordingPublisher.
type Publisher interface {
	Publish(topic string, e Event) error
}

  2. Write the outbox contract as shared SQL + a tiny helper. Every service gets the same two tables; the teaching transport is an in-process drainer goroutine that HTTP-POSTs pending rows to a static subscriber list — Pub/Sub push semantics (at-least-once, redelivery on non-200) with zero cloud dependencies:

    capstone/pkg/outbox/outbox.go (core)
    package outbox

// Shared DDL every service applies — state change + outbox INSERT
// always share one transaction; a separate drainer publishes.
const DDL = `
CREATE TABLE IF NOT EXISTS event_outbox (
  event_id     TEXT PRIMARY KEY,
  event_type   TEXT NOT NULL,
  ordering_key TEXT NOT NULL,
  envelope     TEXT NOT NULL,           -- full wire JSON
  status       TEXT NOT NULL DEFAULT 'pending',  -- pending|published
  created_at   TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE TABLE IF NOT EXISTS consumed_event (
  event_id    TEXT PRIMARY KEY,        -- the dedup ledger
  consumed_at TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);`

// Drainer: every second, POST each pending row to every subscriber;
// mark published only when ALL subscribers returned 2xx. Redelivery
// on failure is the at-least-once semantics consumers must survive.

    Implement the drainer loop yourself (~40 lines: SELECT … WHERE status='pending' ORDER BY created_at, POST the envelope to each subscriber URL, UPDATE … SET status='published' on all-2xx). Keep SQLite per service for the teaching build (one file each: booking.db, billing.db, collections.db) — and notice the two planes: Memgraph holds the DDE metadata about the work (responsibilities, contracts, gates), while each service privately owns its runtime data relationally, exactly as real services own their AlloyDB schemas and never touch the builder's graph. The pattern, not Postgres, is the lesson; note where the real system differs (AlloyDB, a separate drainer service, real Pub/Sub with EnableMessageOrdering).

8.3Build the three servicesstage 5▶

Now build in wave order, to contracts, with the graph watching. Each service follows the canonical Go service anatomy; each consumes events idempotently (dedup ledger + guarded single-winner updates); and you work like the pipeline works: claim the WP, build, test, submit evidence, pass the gate, move status — with findings registered at the point of friction, not remembered at the end.

In the real system

The anatomy is domains/booking/services/svc_handoff_mobilisation/: cmd/ composition root wiring strictly downward; internal/{config,domain,store,transport,health}; Deps struct DI with nil-tolerant defaults; consumer-defined interfaces; sentinel errors + %w; the consumed-event ledger checked at handler entry; guarded UPDATEs where rows-affected 0 means "lost the race, converge quietly". Push ACK/NACK maps to HTTP: nil error → 200 ACK (success, not-eligible, and duplicate are all handled-and-nil); any error → 5xx NACK and the broker redelivers. Full pattern reference: .claude/rules/go-coding-patterns.md.

Tasks

  1. Wave 1–2: mini-booking. Module capstone/services/mini-booking (add to go.work), anatomy: cmd/mini-booking/main.go, internal/{config,domain,store,transport}. Tables: booking_request(id, client_name, total_value, status draft|submitted|booked), contract(sap_contract_number PK, lifecycle_state, booked_at) + the shared outbox DDL.     mini-booking/internal/store/book.go (the load-bearing write)
    // Book flips the request draft→booked, mints the Contract directly at
// 'active' (setup → active collapses into the mint — the booked event
// IS that transition), and inserts the c2c.contract.booked outbox row
// — ONE transaction. There is never a booked-but-unannounced window.
func (s *Store) Book(ctx context.Context, reqID string) (string, error) {
	tx, err := s.db.BeginTx(ctx, nil)
	if err != nil {
		return "", fmt.Errorf("begin: %w", err)
	}
	defer tx.Rollback()

	// Guarded single-winner update: rows-affected 0 = already booked.
	res, err := tx.ExecContext(ctx, `UPDATE booking_request SET status='booked'
		WHERE id=? AND status='submitted'`, reqID)
	if err != nil {
		return "", fmt.Errorf("%w: guard: %v", ErrStore, err)
	}
	if n, _ := res.RowsAffected(); n == 0 {
		return "", ErrConflict // caller maps to 409 / handled-and-nil
	}

	sap := mintSAPNumber() // "SAP-2026-000042"-shaped, sequence from a table
	if _, err := tx.ExecContext(ctx, `INSERT INTO contract
		(sap_contract_number, lifecycle_state, booked_at)
		VALUES (?, 'active', ?)`, sap, now()); err != nil {
		return "", fmt.Errorf("%w: contract: %v", ErrStore, err)
	}

	evt, err := envelopeContractBooked(sap, reqID) // pkg/contracts types
	if err != nil {
		return "", err
	}
	if err := outbox.InsertTx(ctx, tx, evt); err != nil {
		return "", fmt.Errorf("%w: outbox: %v", ErrStore, err)
	}
	return sap, tx.Commit()
}

  2. The consumer template — write once in mini-billing, reuse in collections. Handler entry: dedup, dispatch, ACK/NACK:

    mini-billing/internal/transport/events.go
    // POST /events — the push receiver. Contract: 200 = ACK (consumed),
// 5xx = NACK (the drainer redelivers). Duplicates are handled-and-nil.
func (h *Handler) Events(w http.ResponseWriter, r *http.Request) {
	var evt events.Event
	if err := json.NewDecoder(io.LimitReader(r.Body, 1<<20)).Decode(&evt); err != nil {
		http.Error(w, "bad envelope", http.StatusBadRequest) // poison: don't retry
		return
	}
	fresh, err := h.store.MarkConsumed(r.Context(), evt.ID) // INSERT OR IGNORE
	if err != nil {
		http.Error(w, "ledger", http.StatusInternalServerError) // NACK
		return
	}
	if !fresh {
		w.WriteHeader(http.StatusOK) // duplicate: converge quietly, ACK
		return
	}
	if err := h.dispatch(r.Context(), evt); err != nil {
		http.Error(w, err.Error(), http.StatusInternalServerError) // NACK → redelivery
		return
	}
	w.WriteHeader(http.StatusOK)
}

Three services build and test green in isolation; each consumes idempotently (prove: POST the same envelope twice — one state change); build_exit passes for all three; the graph shows sessions, claims, evidence, verdicts, and findings telling the true story of the build.

Why it exists

The outbox is the distributed-systems lesson of the real repo: every producer writes state + outbox row in one transaction, a drainer publishes, consumers dedup on event_id, and a republish re-sends the same id so a correct consumer converges. Every piece exists because the naive alternative (publish-after-commit, or commit-after-publish) loses or duplicates events under crash — there is no third option, only the outbox.

Why it exists — the whole course in one paragraph

Every mechanism you built is an answer to "what happens under pressure, at scale, with agents?" State machines because statuses will be skipped; server-minted IDs because parallel sessions will collide; contracts-as-schemas because "not built yet" will be used as an excuse; gates-with-evidence because "tests pass, trust me" will be claimed; hooks because rules that live in prose will be ignored — measurably, twice, before they became mechanical. DDE is engineering discipline compiled into infrastructure. Now you've compiled it yourself.
