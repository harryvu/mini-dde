Week 4 · Part II — governance & agents

The MCP server

Agents don't get a database driver — they get tools. MCP (Model Context Protocol) is the interface: each graph operation becomes a named tool with a schema, validation runs at the tool boundary, and the server bakes in project identity so no agent can forget it. By Friday, Claude Code is reading and writing your graph.

  • Concept: tools as the agent interface; one registry, N transports
  • Build: an MCP server over your store with mcp-go
  • Build: full-text search; the graph-first rule
  • Milestone: Claude Code drives your graph
4.1Stand up the MCP servermcp-go▶

The real DDE server registers ~110 tools through one registry function and serves the identical surface over stdio and HTTP — the two transports can never drift because they construct the same server. Dependencies (the store, with project id baked in) enter as constructor closures, never globals. You'll clone that exact shape at 1/20th the tool count.

In the real system

builder/server/main.go:97-108: server.NewMCPServer("nexus-dde", "0.1.0") (the same mark3labs/mcp-go library you're about to use) → tools.RegisterAll(...) → server.ServeStdio(srv). The HTTP transport (internal/mcphttp/handler.go) wraps the same RegisterAll. Identity: --config flag → NEXUS_DDE_CONFIG env → default .nexus-dde/project.yaml; the store is constructed with cfg.ProjectID so every tool inherits scoping for free.

  2. Read project identity from the config file — the same resolution order as the real server:

    server/internal/config/config.go
    package config

import (
	"fmt"
	"os"

	"gopkg.in/yaml.v3"
)

type Config struct {
	ProjectID string `yaml:"project_id"`
	DBPath    string `yaml:"db_path"`
}

// Load: MINIDDE_CONFIG env → default .minidde/project.yaml.
func Load() (Config, error) {
	path := os.Getenv("MINIDDE_CONFIG")
	if path == "" {
		path = ".minidde/project.yaml"
	}
	raw, err := os.ReadFile(path)
	if err != nil {
		return Config{}, fmt.Errorf("config_missing: %s — create it with a "+
			"project_id before serving tools: %w", path, err)
	}
	var c Config
	if err := yaml.Unmarshal(raw, &c); err != nil {
		return Config{}, fmt.Errorf("config_invalid: %w", err)
	}
	if c.ProjectID == "" {
		return Config{}, fmt.Errorf("config_invalid: project_id is required")
	}
	if c.DBPath == "" {
		c.DBPath = "minidde.db"
	}
	return c, nil
}

    Add db_path: "minidde.db" to your .minidde/project.yaml.

  4. Register one heartbeat tool to prove the plumbing before the real surface lands — in registerQueryTools:

    server/internal/tools/query.go
    package tools

import (
	"context"
	"encoding/json"

	"github.com/mark3labs/mcp-go/mcp"
	"github.com/mark3labs/mcp-go/server"

	"minidde/server/internal/graph"
)

func jsonResult(v any) *mcp.CallToolResult {
	b, _ := json.MarshalIndent(v, "", "  ")
	return mcp.NewToolResultText(string(b))
}

func registerQueryTools(srv *server.MCPServer, st *graph.Store) {
	srv.AddTool(
		mcp.NewTool("query_node",
			mcp.WithDescription("Get a single graph node by id."),
			mcp.WithString("id", mcp.Required(), mcp.Description("node id")),
		),
		func(ctx context.Context, req mcp.CallToolRequest) (*mcp.CallToolResult, error) {
			id, err := req.RequireString("id")
			if err != nil {
				return mcp.NewToolResultError(err.Error()), nil
			}
			n, err := st.GetNode(id)
			if err != nil {
				return mcp.NewToolResultError(err.Error()), nil
			}
			return jsonResult(n), nil
		},
	)
}

    Note the error convention: tool-level failures return NewToolResultError (the model sees the message and can react); only transport-level breakage returns a Go error. Your structured code: message errors from week 2 now pay off — the agent can parse them.

  5. Smoke-test over stdio without a client, using the MCP inspector:

    npx @modelcontextprotocol/inspector go run ./server/cmd/minidde mcp

    In the inspector UI: list tools → call query_node with {"id": "booking-core"} → your node comes back as JSON.

Checkpoint

4.2The core tool surfacetool registry▶

Now the real surface: the CRUD and lifecycle tools agents live on. The discipline that matters is schema and handler side by side — each AddTool call declares required params, enums, and descriptions the model reads, then the handler re-validates through your week-2 chains. Schema tells the model what to send; validators decide what's accepted. Belt and suspenders, on purpose.

In the real system

registry.go groups 15 register* functions; every tool is declarative srv.AddTool(mcp.NewTool("name", mcp.WithString(..., mcp.Required())), HandleX(store)). The description strings double as agent documentation — read create_node's in the real repo and notice it teaches the edge contracts inline.

Tasks

4.3Search & the graph-first habitsearch▶

"Query the graph before searching files" only works if the graph is queryable by meaning-ish lookups, not just by id. The real system has two search tools — keyword full-text and semantic/vector — with a routing rule (semantic for concepts, keyword for exact tokens, always bound the result set). You'll build the keyword half with SQLite FTS5 and encode the routing rule as agent context.

In the real system

search (full-text, returns full node bodies — always pass node_types and a small limit) vs semantic_search (Qdrant vectors, lighter payloads, the default for concept lookups) — the selection discipline is .claude/rules/bld-mcp-routing.md § "Tool selection". The learning tools (register_finding, register_escalation, resolve_*) live in their own registry group.

Tasks

  1. Add an FTS5 index kept in sync at write time. In store.go's schema:

    CREATE VIRTUAL TABLE IF NOT EXISTS nodes_fts
  USING fts5(id UNINDEXED, project_id UNINDEXED, body);

    At the end of CreateNode and UpdateNode, upsert the searchable text (delete-then-insert by id is fine):

    server/internal/graph/search.go
    package graph

import (
	"encoding/json"
	"fmt"
)

func (s *Store) indexNode(n Node) {
	body, _ := json.Marshal(n.Props)
	s.db.Exec(`DELETE FROM nodes_fts WHERE id = ? AND project_id = ?`,
		n.ID, s.projectID)
	s.db.Exec(`INSERT INTO nodes_fts (id, project_id, body) VALUES (?, ?, ?)`,
		n.ID, s.projectID, n.ID+" "+string(body))
}

// Search: keyword full-text, bounded. limit <= 20 — an unbounded
// search result is a context-window attack on your own agent.
func (s *Store) Search(query, nodeType string, limit int) ([]Node, error) {
	if limit <= 0 || limit > 20 {
		limit = 10
	}
	rows, err := s.db.Query(`
		SELECT f.id FROM nodes_fts f
		JOIN nodes n ON n.id = f.id AND n.project_id = f.project_id
		WHERE f.project_id = ? AND nodes_fts MATCH ?
		  AND (? = '' OR n.type = ?)
		LIMIT ?`, s.projectID, query, nodeType, nodeType, limit)
	if err != nil {
		return nil, fmt.Errorf("search: %w", err)
	}
	defer rows.Close()
	var out []Node
	for rows.Next() {
		var id string
		rows.Scan(&id)
		if n, err := s.GetNode(id); err == nil {
			out = append(out, n)
		}
	}
	return out, rows.Err()
}

4.4Wire up Claude Code.mcp.json▶

The last mile: register your server with Claude Code, hand the agent a rules file that encodes the working discipline, and watch it drive your graph. This is the moment mini-DDE stops being a database project and becomes an agent platform.

In the real system

.mcp.json registers the dde server (short name mandated by an enterprise whitelist — names are governance too). .claude/rules/bld-knowledge-graph-first.md and bld-mcp-routing.md are always-loaded; bld-use-mcp-tools-directly.md bans piping JSON-RPC into the binary. A PreToolUse hook blocks every mcp__dde__* call when the identity file is missing — you'll build that hook in week 6.

Tasks

  1. Register the server at the repo root:

    .mcp.json
    {
  "mcpServers": {
    "minidde": {
      "type": "stdio",
      "command": "go",
      "args": ["run", "./server/cmd/minidde", "mcp"],
      "env": {}
    }
  }
}

  2. Write the context-plane rule — your first .claude/rules/ file, citing its authority like the real ones do:

    .claude/rules/graph-first.md
    # Knowledge Graph First

<implements>
  <xdr>ADR-sqlite-mini-dde-graph-<your-suffix></xdr>
</implements>

The mini-DDE graph is the source of truth. Query it before searching files.

- `query_responsibility(id)` before working on any Responsibility
- `search(query, node_type, limit)` for concept lookups — ALWAYS pass a limit
- Register findings via `register_finding` — never TODOs in code comments
- Change status ONLY via `update_status` (never `update_node`)
- When you hit a question only the human can answer, `register_escalation`
  with >=2 explicit options and STOP.

  3. Connect and verify. Start (or restart) Claude Code in mini-dde/, run /mcp to confirm minidde is attached, then give it real work, one prompt at a time:

    # prompt 1 — read path
"Query the graph for everything about booking-core and summarize its state."

# prompt 2 — write path with governance
"Create a Responsibility 'billing-core' (domain billing) governed by our
capstone PDR, with a proper eli10. Then move it to NOT_STARTED."

# prompt 3 — the learning loop
"Review server/internal/graph/*.go for error-handling gaps. Register a
finding for the worst one you find, severity medium, affecting booking-core."

  4. Watch for the two classic failures and enjoy your guards catching them: the agent inventing its own finding id (blocked — server allocates), and the agent trying update_node with a status (blocked with the remedy in the message). When a guard fires, read the transcript: the structured error told the agent how to self-correct. That's the design working.

  5. Commit everything, including .mcp.json and the rules file — agent context is code.

Checkpoint — end of week 4

All three prompts succeed with the agent using only MCP tools (no sqlite3 shell calls — check the transcript). ls --type Finding shows the agent's finding, edges intact, id server-minted.

Why it exists

Why ban piping JSON-RPC into the binary when tools exist? Because a second access path is a second place where validation can drift — the real rule exists because agents did discover echo '{"jsonrpc"...}' | go run . as a workaround when a tool was missing. Every capability gap becomes an escalation, never a bypass.
